# 发布版本

Release 标题由工作流统一生成为 `Sniffy <版本号>`，正文使用中文产品定位、版本变更、下载安装与文档区块。

## 自动生成

日常发布继续使用轻量标签：

```bash
git tag v0.1.0-beta.2
git push origin v0.1.0-beta.2
```

工作流从当前标签提交的完整历史中查找最近的其他 `v*` 发布标签作为基线，采用 `git describe --tags` 的选择规则，覆盖合并提交的所有父链及同一提交上的其他标签。基线与当前标签指向同一提交时，说明中标明没有新提交；找不到基线时汇总当前标签可达的全部非合并提交。

基线至当前标签之间的非合并提交按标题生成“新增功能”“优化改进”“问题修复”和“其他更新”小节。提交标题推荐使用以下格式：

```text
新增：支持……
优化：完善……
修复：解决……
维护：升级……
```

没有正文的 annotated tag 同样使用自动生成内容。

## 手写正文

重要版本可将人工整理的中文说明写入 annotated tag 正文。工作流检测到正文后直接使用，不再列出提交标题。

发布说明文件可按以下结构编写：

```markdown
Sniffy 0.2.0

本版本的主要变化摘要。

## 新增功能

- 功能说明

## 优化改进

- 改进说明

## 问题修复

- 修复说明
```

创建标签时必须保留 Markdown 标题：

```bash
git tag -a v0.2.0 --cleanup=verbatim -F release-notes.md
git push origin v0.2.0
```

工作流会在测试与构建全部通过后创建 Release，并自动补充安装包、校验和与相关文档说明。
