## 导出会话

<Endpoint method="POST" path="/api/export" />

按过滤条件流式返回 HTTP 会话。默认 `format=json` 返回会话数组；`format=har` 返回 HAR 1.2 档案。接口先获取会话 ID 列表，再逐条读取；导出期间发生的更新、删除或容量淘汰可能影响结果。

```bash
curl -s -X POST $SNIFFY_API/api/export \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"hosts": ["api.example.com"], "statusCodes": [500]}' \
  -o sessions.json
```

| 响应头                | 值                                          |
| --------------------- | ------------------------------------------- |
| `Content-Type`        | `application/json`                          |
| `Content-Disposition` | `attachment; filename="sessions.json"`      |
| `Cache-Control`       | `no-store`                                  |

JSON 导出响应**不走包络**，直接是一个数组：

```json
[ { "id": "…", "request": { }, "response": { } } ]
```

数组元素的结构与 `/api/sessions` 返回的会话完全一致，见[会话](/docs/api/sessions/#会话结构)。

## 过滤条件

全部字段可选。空请求体表示导出全部。

| 字段                  | 类型     | 默认   | 说明                                        |
| --------------------- | -------- | ------ | ------------------------------------------- |
| `format`              | string   | `json` | 支持 `json` / `har`；空串等价于 `json`                 |
| `sessionIds`          | string[] | —      | 只导出这些会话                              |
| `methods`             | string[] | —      | 方法白名单，**不区分大小写**                |
| `hosts`               | string[] | —      | 主机白名单，匹配时**忽略端口**              |
| `statusCodes`         | number[] | —      | 状态码白名单，取值须在 100–999              |
| `timeRange.start`     | string   | —      | 起始时刻，RFC3339                           |
| `timeRange.end`       | string   | —      | 结束时刻，RFC3339                           |
| `includeRequestBody`  | boolean  | `true` | 是否带请求体                                |
| `includeResponseBody` | boolean  | `true` | 是否带响应体                                |

多个条件之间是**且**的关系，同一条件内的多个取值之间是**或**的关系。

### 完整例子

```json
{
  "format": "json",
  "methods": ["GET", "POST"],
  "hosts": ["api.example.com"],
  "statusCodes": [500, 502, 503],
  "timeRange": {
    "start": "2026-09-17T00:00:00Z",
    "end": "2026-09-17T23:59:59Z"
  },
  "includeRequestBody": true,
  "includeResponseBody": false
}
```

### 几条匹配细节

- **主机**先按原值（含端口）比一次，不中再去掉端口比一次。所以 `api.example.com` 能命中 `api.example.com:8443`。比较不区分大小写。
- **状态码**只对有响应的会话生效：给了 `statusCodes` 之后，尚未完成的会话一律不匹配。
- **时间范围**按请求开始时刻筛选，两端都是闭区间。只给 `start` 或只给 `end` 都可以。请求时刻为空的会话在设了时间范围时不匹配。
- **空值与空白**会被跳过：`{"hosts": ["", "  "]}` 等价于没给这个条件。

## 正文的边界

:::caution
JSON 导出的 `body` 是会话结构里的**文本预览**，上限 1 MiB。

二进制正文、超大正文、走透传旁路的正文在这里拿不到完整内容——它们要用 [`/api/sessions/{id}/body/raw`](/docs/api/sessions/#原始字节流) 单独取。`size` 字段永远是真实字节数，可以据此判断预览是否完整。
:::

只需要时间、状态码、耗时、URL 等元数据时，可关闭两个 `include*Body` 选项以减少导出体积：

```json
{ "includeRequestBody": false, "includeResponseBody": false }
```

## 严格解码

此端点拒绝未知字段，字段名错误时返回 400。

```bash
# 拼错了 host -> hosts
curl -s -X POST $SNIFFY_API/api/export \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"host": ["api.example.com"]}'
# {"success":false,"message":"invalid json",...}
```

请求体必须恰好是一个 JSON 值，上限 64 KiB。

## 常见用法

**CI 里归档某个域名的全部往返**

```bash
curl -s -X POST $SNIFFY_API/api/export \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"hosts":["api.example.com"]}' > artifacts/sessions.json
```

**只导出失败的请求**

```bash
curl -s -X POST $SNIFFY_API/api/export \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"statusCodes":[500,502,503,504]}' \
| jq -r '.[] | "\(.response.status) \(.request.method) \(.request.url)"'
```

**导出刚才那批会话**

先从会话列表取 id，再按 id 精确导出：

```bash
ids=$(curl -s "$SNIFFY_API/api/sessions?pageSize=20" \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" | jq -c '[.data[].id]')

curl -s -X POST $SNIFFY_API/api/export \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"sessionIds\": $ids}"
```

**统计每个主机的请求数**

```bash
curl -s -X POST $SNIFFY_API/api/export \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"includeRequestBody":false,"includeResponseBody":false}' \
| jq -r '.[].request.host' | sort | uniq -c | sort -rn
```

## HAR 1.2

设置 `format: "har"` 导出 HAR 档案，下载文件名为 `sessions.har`：

```bash
curl -s -X POST $SNIFFY_API/api/export \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"format":"har"}' -o sessions.har
```

```json
{ "log": { "version": "1.2", "creator": { "name": "Sniffy", "version": "…" }, "entries": [] } }
```

HAR 导出读取完整保留的正文，包括磁盘缓存的响应体。重复头在数组中逐条保留；请求和响应分别记录 MIME 类型。二进制响应体使用 `content.encoding: "base64"`，二进制请求体使用 `postData._encoding: "base64"` 扩展字段。含非 UTF-8 字节的头值额外带 `_valueBase64`。

来源未保留的正文无法恢复。磁盘缓存丢失会中断下载，客户端须拒绝不完整的 JSON。导出逐条编码，内存开销随最大单条正文增长。

桌面「流量」菜单导出当前筛选范围内的 HTTP 与 WebSocket 会话。WebSocket 消息采用 Chromium 的 `_webSocketMessages` 扩展字段。HAR 档案可用于浏览器 DevTools、Charles 等支持 HAR 1.2 的工具。

## 状态码

| 状态码 | 含义                                                       |
| ------ | ---------------------------------------------------------- |
| 200    | 成功，响应体随格式返回 JSON 会话数组或 HAR 档案                                     |
| 400    | JSON 畸形、未知字段、`format` 不支持、状态码越界、时间格式错误、`start` 晚于 `end` |
| 401    | token 缺失或不匹配                                         |
| 405    | 方法不是 POST                                              |
| 413    | 请求体超过 64 KiB                                          |

响应是流式写出的：一旦开始写响应，中途出错不会改状态码，只会让 JSON 截断。解析失败时先确认响应是不是完整的。

## 导入会话

<Endpoint method="POST" path="/api/import" />

请求体直接发送 HAR 1.2 档案内容，上限 128 MiB：

```bash
curl -s -X POST $SNIFFY_API/api/import \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data-binary @sessions.har
```

```json
{ "success": true, "data": { "imported": 12, "http": 10, "webSocket": 2, "ids": ["…"] } }
```

导入先校验整个档案，再追加会话，每次分配新 ID，`ids` 返回这些新 ID。已有记录按配置的容量上限保留，超出容量会淘汰最早入库的记录。暂停录制时仍可导入；导入还原离线记录，不发送请求，也不计入实时抓包统计。WebSocket 会话还原为关闭状态。

桌面「流量」菜单提供**导入 HAR/JSON…**，完成后显示导入数量，当前筛选条件继续生效。文件格式错误返回 400，请求体超限返回 413。请求正文优先取自 `postData.text`；仅有 `postData.params` 时可还原 URL 编码表单，无法还原的文件或 multipart 参数返回 400。响应正文取自 `content.text`，来源未保留的正文保持缺失，请求的已知 `bodySize` 会保留。HAR 1.2 档案使用 `.har` 或 `.json` 扩展名均可导入。
