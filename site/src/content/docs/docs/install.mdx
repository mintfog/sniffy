## 选择形态

| 形态                    | 适合                                   | 交互方式                     |
| ----------------------- | -------------------------------------- | ---------------------------- |
| 桌面版                  | 日常抓包、界面化改写与调试             | 原生窗口                     |
| 无界面版（headless）    | 服务器、容器、CI，以及脚本化的自动调试 | REST + WebSocket             |

拿不准就先装桌面版。两者的抓包引擎、规则引擎和插件系统是同一套，配置与规则也都放在同一个目录，所以同一台机器上可以交替使用，在桌面版里调好的规则，换成无界面版启动照样生效。

## 桌面版

点击文件名即可下载对应平台的安装包：

<Downloads edition="desktop" />

也可以从 [GitHub Releases](https://github.com/mintfog/sniffy/releases) 下载。鼠标停在文件名上会显示 SHA256 校验值。

### Windows

运行 `.exe` 安装程序，按向导装完即可。SmartScreen 若弹出「已保护你的电脑」，点「更多信息 - 仍要运行」。

如果启动后窗口一片空白，多半是系统缺少 WebView2，装上 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) 再打开。

### macOS

打开 `.dmg`，把 Sniffy 拖进「应用程序」。

安装包还没有经过 Apple 公证，第一次打开会被系统拦下。放行有两种办法，任选其一：在「应用程序」里右键 Sniffy 选「打开」，再在弹窗里确认；或者到「系统设置 - 隐私与安全性」，对被拦截的应用点「仍要打开」。放行一次后，之后正常双击就能启动。

如果提示应用「已损坏」，先确认两件事：安装包来自本站下载页或本项目的 Releases 页面，并且下载完整（可以对照上面的 SHA256）。两者都没问题，执行下面这条命令后再打开：

```bash
xattr -dr com.apple.quarantine /Applications/Sniffy.app
```

### Linux

`.deb` 适用于 Debian、Ubuntu 及其衍生版：

```bash
sudo apt install ./sniffy-desktop-linux-amd64-installer.deb
```

用 `apt install` 而不是 `dpkg -i`，apt 会顺带装上缺少的依赖。装好后从应用菜单启动，或在终端运行 `sniffy`。

其他 linux 发行版暂无安装包，可以从源码构建，或者在容器里跑无界面版

## 无界面版

headless 可执行文件按 `sniffy-<os>-<arch>` 命名，下载后就能运行，不需要安装别的东西：

<Downloads edition="headless" />

```bash
chmod +x sniffy-linux-amd64
./sniffy-linux-amd64 -version
./sniffy-linux-amd64
```

第二行命令只打印版本号，用来确认文件下载无误；第三行才真正启动。

默认代理端口是 `8080`，同一局域网的设备可以直接连。管理 API 在本机的 `8888` 端口，调用时要带 token，token 文件的路径会打印在首次启动的日志里。端口、token 和部署方式见[无界面版](/docs/headless/)。

## 从源码构建

需要 Go 1.26+，构建桌面版还需要 Node.js 22.12+。构建脚本是 bash 写的，Windows 下请在 Git Bash 里运行。

```bash
git clone https://github.com/mintfog/sniffy.git
cd sniffy
```

构建无界面版，可以一次编译多个平台，产物在 `dist/`：

```bash
bash scripts/build.sh headless linux/amd64 darwin/arm64 windows/amd64
```

构建桌面版，产物是 `dist/sniffy-desktop`（Windows 下为 `sniffy-desktop.exe`）：

```bash
bash scripts/build.sh desktop
```

macOS 和 Linux 构建桌面版需要先装好系统的 webview 开发包，Linux 上是 WebKitGTK 及其开发头文件，Windows 不需要额外准备。

## 数据存放位置

| 用途   | 位置                                                               |
| ------ | ------------------------------------------------------------------ |
| 配置区 | Linux `~/.config/sniffy`、macOS `~/Library/Application Support/sniffy`、Windows `%AppData%\sniffy` |
| 缓存区 | Linux `~/.cache/sniffy`、macOS `~/Library/Caches/sniffy`、Windows `%LocalAppData%\sniffy` |

配置区存放 `config.json`、`rules.json`、日志、用户插件与证书，两种形态读的都是这一份。

缓存区放的是可以重新得到的东西，比如较大的响应体，随时可以删。完整说明见[配置参考](/docs/configuration/)。

## 升级

### 桌面版

当有新版本发布时，状态栏会出现提示。点开后在「关于」窗口下载安装包，文件保存在系统的「下载」目录，再按平台完成安装：

- **Windows**：点「立即安装」并确认系统授权。Sniffy 会自行关闭，装完后自动重新打开。
- **macOS**：点「打开安装镜像」，退出 Sniffy，把镜像里的 Sniffy 拖进「应用程序」替换旧版本。
- **Linux**：点「打开所在文件夹」，退出 Sniffy，再执行 `sudo apt install ./sniffy-desktop-linux-amd64-installer.deb`。

规则、插件和根证书都在配置区，覆盖安装不会影响他们。

自动检查可以在「设置 - 关于」里关掉。「关于」窗口中的「跳过此版本」只跳过当前这一版，下一个版本发布时还会提醒你。

### 无界面版

无界面版只在日志里提示新版本，不会自动安装。从上面的下载区拿到新的可执行文件，替换旧文件后重启服务，配置会沿用原来的

## 卸载

Windows 在「应用和功能」里卸载，macOS 直接删除应用，Linux 执行 `sudo apt remove sniffy`。

卸载只删除程序本身，配置区、缓存区和装进系统信任库的 Sniffy Root CA 都还保留，如果后续不再使用 Sniffy 的话，手动删掉这两个目录，再按 [HTTPS 解密与根证书](/docs/https/#移除根证书) 里的步骤把根证书从信任库移除。光删目录不够，证书还在信任库里，系统就会继续信任它。
