断点用于在请求发往上游前或响应返回客户端前暂停流量。暂停后，可以查看内容、手动修改，再选择放行或阻断。

适用于临时修改单次请求、验证异常参数的处理，或在复现问题时替换响应。

打开左侧**断点**页面（`Alt+B`）。

## 两种触发方式

<Screenshot src="breakpoints-overview.png" alt="断点页面：全局断点开关、URL 规则列表与暂停中的请求" caption="断点页面" />

### 全局断点

两个开关，分别对**所有**流量在两个阶段生效：

- **请求断点** —— 请求发往上游之前暂停，可以改方法、URL、请求头、请求体。
- **响应断点** —— 响应返回客户端之前暂停，可以改状态码、状态文本、响应头、响应体。

全局断点会暂停所选阶段的所有流量，打开网页时可能同时产生多条暂停记录。可使用「全部放行」或「全部阻断」批量处理。

### 断点规则

更常用的是按 URL 限定。点「添加规则」，填 URL 模式并勾选要拦截的阶段：

- 不含 `*` 时按**子串包含**匹配：`/api/pay` 能命中任何路径里带这段的 URL。
- 含 `*` 时按**整串通配**匹配：`https://api.example.com/*/orders` 要求整个 URL 与模式对上，`*` 匹配任意字符。模式里的 `.`、`?`、`+` 等按字面量处理。

每条规则可以单独启停与删除。全局开关与规则是**或**的关系，任一命中就会暂停。

## 处置暂停中的请求

命中的流量出现在「暂停的请求」列表里，每条标明暂停在哪个阶段，并显示倒计时。

| 操作         | 效果                                                       |
| ------------ | ---------------------------------------------------------- |
| **原样放行** | 不做修改继续                                               |
| **编辑**     | 打开编辑器，改完以「放行（带修改）」继续                   |
| **阻断**     | 结束这条流量，客户端会看到连接被重置                       |
| **续期**     | 重新开始计时，用于需要更久的编辑                           |
| **全部放行** / **全部阻断** | 一次处置列表里的所有条目               |

### 超时会自动放行

每条暂停记录的默认期限为 **5 分钟**。超时后自动原样放行，未提交的编辑不会生效，界面会显示「已超时自动放行」。

同时暂停的上限为 **100 条**。达到上限后，新流量会跳过断点并继续处理。

## 编辑器

<Screenshot src="breakpoints-editor.png" alt="断点编辑器：头部与正文两个页签，底部是放行与阻断按钮" caption="断点编辑器" />

「编辑并放行」分头部与正文两个页签。

请求侧可改**请求方法**、**URL**、头部与正文；响应侧可改**状态码**、**状态文本**、头部与正文。正文编辑器有「格式化 JSON」按钮，放行时会按新内容重算长度。

有几类正文不会载入编辑器，编辑器会明确说明原因，并在放行时原样保留：

| 情况           | 原因                                                       |
| -------------- | ---------------------------------------------------------- |
| 正文不是文本   | 二进制内容经文本编辑器往返会损坏字节                       |
| 超过编辑上限   | 上限 2 MiB，更大的正文不整体读进编辑器                     |
| 透传响应       | 正文边接收边转发，不整体载入编辑器                         |
| 流式响应       | 正文由上游逐条中继                                          |

后两种情况下**状态行与响应头照常可改并生效**，只有正文不可编辑。

部分头部会在发送时根据最终报文重新计算，例如 `Content-Length`。编辑器会标注这些字段，手动修改不会覆盖自动计算的结果。

关闭编辑器会丢弃这次的全部修改，但请求仍留在断点上等待处置，不会因此被放掉。

## 断点与规则、插件的关系

断点可以与规则、插件同时使用。一条流量被改写后仍可在断点处暂停；放行后，规则或插件已决定的处理方式（继续、Mock 或阻断）仍然生效。

插件也可以主动触发断点，在 `onRequest` 或 `onResponse` 里调用 `setBreakpoint()`，让满足复杂条件的流量停下来等人处理。见 [JavaScript 插件](/docs/plugins/)。

## headless 下的断点

管理 API 提供完整的断点能力，命中时经 `/api/ws` 推送 `breakpoint_hit` 事件，处置后推送 `breakpoint_resolved`。

```bash
# 开启全局请求断点
curl -X PUT http://127.0.0.1:8888/api/breakpoints/global \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"onRequest": true, "onResponse": false}'

# 列出暂停中的条目
curl http://127.0.0.1:8888/api/breakpoints \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN"

# 带修改放行
curl -X POST http://127.0.0.1:8888/api/breakpoints/{id}/resume \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"request": {"headers": [["X-Debug", "1"]], "body": "{}"}}'

# 原样放行
curl -X POST http://127.0.0.1:8888/api/breakpoints/{id}/resume \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN"
```

放行请求体是编辑补丁，只需提供要修改的字段。省略 `headers` 或设为 `null` 时保留原有头部；提供数组时整体替换，`[]` 表示清空。未知字段会返回 400。请按补丁结构提交，暂停快照中的正文使用 base64，补丁中的 `body` 使用文本。

完整端点见[管理 API 参考](/docs/api/breakpoints/)。
