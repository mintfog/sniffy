请求构造器用于编辑并发送请求。可以从已捕获的请求创建草稿，也可以新建请求来调试接口。

打开方式：

- 流量列表右键一行 - **编辑后重发**（或按 `Shift+R`），构造器会带着这条请求的原始内容打开。
- 菜单「流量 - 新建请求」或 `Ctrl/Cmd+N`，打开空白构造器。

构造器在独立窗口里工作，支持多页签，可以同时留着几条请求来回比对。

## 四种模式

<Screenshot src="compose-window.png" alt="请求构造器窗口：左侧请求编辑，右侧响应，顶部是模式与页签" caption="请求构造器" />

| 模式          | 用途                                                     |
| ------------- | -------------------------------------------------------- |
| **HTTP**      | 普通的一次性请求响应                                     |
| **GraphQL**   | 分开填查询、变量与操作名，自动合成 POST 的 JSON 请求体    |
| **SSE**       | `text/event-stream`，事件逐条追加显示，可随时停止         |
| **WebSocket** | 建立连接后手动收发消息                                   |

另有**从 cURL 导入**，见下文。

## HTTP

左侧填请求，右侧看响应。方法、URL、请求头、请求体各占一块。

- 请求头以有序列表编辑，保留输入的大小写与重复项，并按列表顺序发送。「常用请求头」下拉菜单提供常见头名。
- 填了 JSON 请求体但没有 `Content-Type` 时，会出现一个「补上 Content-Type」的快捷按钮。
- 请求体旁的「格式化」把 JSON 排版好。

`Ctrl/Cmd+Enter` 发送。响应区在等待期间显示进行状态，失败时说明原因。

### 出站报文预览

「出站报文」面板预览发送时的报文，并标注会被重新计算或移除的头部。例如，`Content-Length` 会根据最终请求体重新计算。

### 编辑已捕获的请求

从已捕获的请求打开时，顶部标注「源自已捕获的请求」，左侧用蓝色竖条标出改动过的字段，便于对照原始请求。发出的请求会作为一条新会话出现在流量列表里。

二进制请求体或超过编辑上限的请求体不会载入编辑器，界面会提示具体原因。发送前请确认请求体是否符合预期。

## 从 cURL 导入

<Screenshot src="compose-curl-import.png" alt="从 cURL 导入的草稿，顶部提示条列出导入时发生的改动" caption="cURL 导入" />

浏览器开发者工具里右键一条请求 - 「复制为 cURL」，粘进导入框即可得到一份可编辑的草稿。方法、URL、头部、请求体、`-u` 认证、`--compressed` 都会被翻译过来。

导入后，请查看提示中列出的不支持或已调整的选项：

- `-L`（跟随重定向）被忽略——构造器不自动跟随，30x 原样返回。
- `-x`（代理）被忽略——构造器走设置里的上游代理。
- `@file` 形式的请求体读不到文件，会被丢弃；`multipart` 的文件部分只导入空占位。
- HTTP/2 伪头被丢弃，它们在 HTTP/1.1 报文里没有位置。
- 不支持 PowerShell 格式的命令，请在开发者工具中选择「复制为 cURL (bash)」或「cURL (cmd)」。

## GraphQL

查询、变量、操作名分三块填写，请求以 POST 发出，JSON 请求体由这三项合成。变量必须是合法 JSON，不合法时会指出原因且不会发出。

响应体包含 `errors` 时，构造器会显示 GraphQL 错误数量，即使 HTTP 状态码为 200。

## SSE

填好 URL 点击「连接」，事件逐条追加到右侧，带计数。随时可以「停止」结束这条流。

服务端返回的内容类型不是 `text/event-stream` 时，构造器会显示提示，并以普通响应体展示内容。

不切到 SSE 模式也可以：用 HTTP 或 GraphQL 模式发出的请求，如果服务端返回的是事件流，构造器同样会逐条显示事件，发送按钮变成「停止」。

## WebSocket

填 `ws://` 或 `wss://` 地址后点击「连接」。连上之后：

- 消息框输入内容，`Ctrl/Cmd+Enter` 发送。
- 类型可选**文本**或**二进制**，二进制按 base64 输入。
- 收发的每一帧都列在下方，带方向与计数。
- 「断开」主动关闭连接。

## 经插件与规则

构造器顶部有一个「经插件与规则」开关：

- **关闭**（默认）—— 按构造器中的配置发送，跳过重写规则、插件与断点。
- **开启** —— 这次请求照常走完整管道，用来验证规则或插件对某条具体请求的效果。

对于 WebSocket，此开关仅控制消息是否经过插件的 WebSocket 钩子。握手不经过处理管道，消息不适用重写规则与断点。

## headless 下的构造器

管理 API 提供同样的能力：

```bash
curl -X POST http://127.0.0.1:8888/api/compose \
  -H "Authorization: Bearer $SNIFFY_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
        "method": "GET",
        "url": "https://example.com/api/users",
        "headers": [["Accept", "application/json"]],
        "body": "",
        "viaPipeline": false
      }'
```

返回的是新会话的 `flowId`，**往返是异步的**：响应经 `/api/ws` 的事件推送，或稍后用 `GET /api/sessions/{id}` 取。

WebSocket 与流式请求的控制端点见[管理 API 参考](/docs/api/compose/)。
