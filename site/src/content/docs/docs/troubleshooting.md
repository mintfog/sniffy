## 什么流量都抓不到

按以下顺序检查代理状态与客户端配置：

1. **检查监听状态** —— 代理栏应显示「监听中 :8080」。端口被占用时启动会失败，请更换端口。
2. **验证客户端代理配置** —— 用以下请求测试：
   ```bash
   curl -v --proxy http://127.0.0.1:8080 http://example.com
   ```
   如果请求出现在列表中，说明该请求已成功经过 Sniffy。接下来检查目标程序是否使用了相同的代理地址。
3. **核对端口** —— 客户端配置的端口需与 Sniffy 的监听端口一致。
4. **检查录制状态** —— 暂停时代理仍在监听，但不会记录新流量。

### 开了系统代理但某个程序抓不到

不是所有程序都读系统代理设置。常见的例外：

- 用 Go、Rust 写的命令行工具通常只读 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量。
- Java 程序需要 `-Dhttp.proxyHost` 一类系统属性。
- Node.js 的 `fetch` 默认不走代理，需要显式配置 `undici` 的 ProxyAgent。
- 部分应用内置了代理绕过规则，或使用 QUIC / HTTP3 直接出网。

对应做法见[接入流量](/docs/capture/#手动配置单个程序)。

### 只看到 CONNECT，看不到具体请求

HTTPS 流量可能处于隧道转发状态。按下面的步骤检查证书信任与解密范围。

## HTTPS 解密不出来

### 检查根证书信任

通过 Sniffy 访问 HTTPS 站点，并在浏览器中查看证书信息。使用默认 CA 时，签发者为 **Sniffy Root CA** 表示该连接已解密；若仍是源站证书，请检查代理配置和解密范围。若出现证书错误，请检查客户端是否信任 Sniffy 根证书。

### 装了证书仍然不解密

继续检查以下情况：

1. **iOS 根证书信任未开启** —— 安装描述文件后，还需到「设置 - 通用 - 关于本机 - 证书信任设置」开启信任。
2. **浏览器尚未加载新的信任设置** —— 安装证书后重启浏览器再试。
3. **解密范围把它排除了** —— 检查「设置 - HTTPS 解密」的范围与名单。
4. **Linux 浏览器使用独立的证书库** —— 部分浏览器需要将证书导入 NSS 库。安装时若缺少 `certutil` 或证书库被占用，可在浏览器设置中手动导入。
5. **Android 应用不信任用户 CA** —— 面向 API 24 及以上的应用默认只信任系统 CA，具体取决于应用配置。见[移动设备与远程客户端](/docs/mobile/#4-确认应用是否支持)。
6. **目标做了证书固定** —— 见下。

### 证书固定（certificate pinning）

应用把预期的证书或公钥硬编码在自己内部，看到 Sniffy 签发的证书就拒绝连接。表现是这个域名一律连接失败，而其他站点正常。

可根据应用是否由你维护，选择以下处理方式：

- 把该域名加进**解密黑名单**让它直通，这样应用能正常工作，你也仍然能看到连接的目标与流量大小。
- 调试自己的应用时，在 debug 构建里关掉固定。

### 出站方向报证书错误

Sniffy 去连真正的服务端时也会完整校验证书。源站用自签证书、或证书已过期时，会停止转发并记下错误。

内部 CA 可导入 Sniffy 所在系统的信任库，重启后重试；证书过期或域名不匹配时，请更新服务端证书。受控调试环境可配置主机级例外，见[配置参考](/docs/configuration/#出站-tls-例外)。

## 手机连不上代理

1. **检查网络连通性** —— 设备需能访问运行 Sniffy 的机器。部分公司或公共 Wi-Fi 的客户端隔离会阻止设备间连接。
2. **地址填对了吗** —— 要填运行 Sniffy 的机器的**内网地址**，不是 `127.0.0.1`。代理栏的网络菜单会列出可用地址；同时接了 Wi-Fi 和网线时选与手机同网段的那个。
3. **防火墙放行了吗** —— Windows 首次监听时会弹出防火墙询问，选了「取消」就需要去防火墙设置里手动放行。macOS 与 Linux 上检查本机防火墙规则。
4. **检查代理认证** —— Android 的 Wi-Fi 手动代理通常无法填写凭据，启用认证时可能收到 407。可在可信网络内关闭代理认证后测试。

## 系统代理相关

### Sniffy 退出后无法上网

系统代理设置还指着一个已经不存在的端口。重新启动 Sniffy 并点击「关闭系统代理」，或者在系统设置里手动把代理关掉。

### Linux 上开不了系统代理

目前只支持基于 GNOME 的桌面环境（通过 `gsettings`）。其他桌面请手动配置代理，或用环境变量的方式。

### macOS 上开了系统代理但不生效

`networksetup` 只会改**当前启用**的网络服务。如果刚切换过网络（比如从 Wi-Fi 切到有线），重新点一次开启按钮。

## 改写不生效

### 规则没生效

1. 确认规则已启用。
2. 检查匹配条件。`url_host` 包含端口，`url_path` 不含查询串；可先用 `url` + `contains` 验证匹配，再缩小范围。
3. 检查执行优先级。较早执行的 `block` 或 `auto_respond` 动作会停止后续规则。
4. 只看响应的条件（`response_status`、`response_header`）在请求阶段取不到值，此时判为不匹配——把它和改请求的动作放在同一条规则里，动作不会执行。

### 插件没生效

1. 确认插件已启用。加载失败时，插件列表会显示错误信息。
2. 检查 URL 黑白名单。命中黑名单会跳过该插件；白名单为空时不限制匹配范围。
3. 在钩子中添加 `console.log`，通过日志面板确认调用情况。
4. **检查执行耗时** —— 每次钩子调用默认限时 100 毫秒，超时后该次改写结果不会应用。请检查日志并减少耗时操作。
5. **检查脚本异常** —— 异常信息会记录在日志面板中。异常发生前的对象修改可能保留，请检查脚本执行顺序。

### 插件读不到响应正文

响应有内容但 `flow.response.body` 为空时，先检查二进制字段 `bodyB64`。以下两类响应不提供完整正文：

- **流式响应**（SSE / gRPC / NDJSON）—— 用 `onStreamMessage` 逐条改写。
- **透传响应**（媒体类型 / 206 / 超过大小阈值）—— 正文不整体缓冲。需要整体改写时关闭 `largeBodyPassthrough`。

见 [JavaScript 插件](/docs/plugins/#什么时候拿不到完整正文)。

### 改了头却没发出去

部分头部在发送时会被重新计算或移除，例如 `Content-Length` 会根据正文长度计算。可在构造器的「出站报文」面板或断点编辑器中查看对应提示。

## 断点相关

### 请求被放行了但我没点

每条暂停项有 5 分钟期限，到点**原样自动放行**，你未保存的修改不会生效，列表里会标出「已超时自动放行」。需要更久就点「续期」。

### 全局断点暂停了过多请求

网页可能同时发出多条请求，全局断点会将其全部暂停。可先使用「全部放行」，再改用 URL 规则限定需要暂停的流量。

### 断点没触发

同时暂停的上限为 100 条。达到上限后，新流量会跳过断点；请先处理暂停列表中的记录。

## 管理 API 相关

### 401 unauthorized

检查 token 是否缺失或与当前实例使用的值一致。管理 API 在回环地址上也要求认证。下例读取 Linux 默认配置目录中的 token：

```bash
cat ~/.config/sniffy/api_token
```

如果启动日志提示「检测到 API token 文件权限过宽」，说明本次启动已轮换 token，请重新读取文件并更新客户端凭据。

### 403 跨站请求被拒

从浏览器页面连 `/api/ws` 时，升级请求的 `Origin` 必须与 `Host` 同源，否则被拒。在本机页面里直接用 `127.0.0.1:8888` 作为地址，不要经由别的域名或端口。

### 405 method not allowed

检查请求方法是否与端点文档一致。响应的 `Allow` 头列出可用方法；同一路径的读取与写入可能使用不同方法，例如插件源码用 `GET` 读取、`PUT` 写入。

### 404 unknown action

检查路径是否有拼写错误或多余的子路径，例如 `/api/sessions/{id}/typo`。请按端点文档修正路径。

### 启动时拒绝绑定非回环地址

管理 API 绑定非回环地址且未启用 TLS 时，默认拒绝启动。请通过 `-api-tls-cert` / `-api-tls-key` 启用 HTTPS；已由 TLS 反向代理或 VPN 保护的部署可使用 `-allow-insecure-api`。

## 性能与资源

### 列表卡顿、内存涨得快

- 降低 `maxFlows`，超出容量后最早的会话会被丢弃。
- 确认已启用 `largeBodyPassthrough`。关闭后，符合旁路条件的大响应会整体缓冲，占用更多内存。
- 缩小解密范围：不需要看内容的域名走直通，开销小得多。
- 定期清空流量。

### 缓存目录越来越大

缓存区存的是大响应体的落盘副本，随时可以整个删掉，见[配置参考](/docs/configuration/#缓存区)。

## 日志在哪

配置区的 `logs/`，按天滚动，保留 7 天。headless 加 `-v` 打开详细日志。

## 还是没解决

在 [GitHub Issues](https://github.com/mintfog/sniffy/issues) 提一个 issue，附上：

- Sniffy 版本（「设置 - 关于」或 `sniffy -version`）
- 操作系统与版本
- 复现步骤
- 相关日志片段与必要的脱敏信息
