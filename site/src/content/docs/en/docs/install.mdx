## Which edition do you need

| Edition          | Good for                                              | How you interact  |
| ---------------- | ----------------------------------------------------- | ----------------- |
| Desktop app      | Everyday capture, editing and debugging with a UI     | A native window   |
| Headless service | Servers, containers, CI, and scripted debugging       | REST + WebSocket  |

If you're not sure, start with the desktop app. Both editions share the same capture engine, rule engine, and plugin system, and they read the same configuration directory, so you can switch between them on one machine: rules you set up in the desktop app take effect when you start the headless service.

## Desktop app

You can also download them from [GitHub Releases](https://github.com/mintfog/sniffy/releases). Hover over a file name to see its SHA256 checksum.

### Windows

Run the `.exe` and follow the wizard. If SmartScreen shows the "Windows protected your PC" prompt, choose "More info - Run anyway".

If the window stays blank after launch, WebView2 is most likely missing; install [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) and open Sniffy again.

### macOS

Open the `.dmg` and drag Sniffy into Applications.

The app isn't notarized by Apple yet, so macOS blocks the first launch. Either right-click Sniffy in Applications, choose "Open", and confirm in the dialog, or go to System Settings - Privacy & Security and click "Open Anyway" for the blocked app. After you allow it once, it opens normally.

If macOS says the app is damaged, check two things first: the installer came from this site's download page or the project's Releases page, and the download is complete (compare it against the SHA256 above). If both check out, run this and open Sniffy again:

```bash
xattr -dr com.apple.quarantine /Applications/Sniffy.app
```

### Linux

The `.deb` targets Debian, Ubuntu, and derivatives:

```bash
sudo apt install ./sniffy-desktop-linux-amd64-installer.deb
```

Use `apt install` rather than `dpkg -i` so apt pulls in any missing dependencies. Then launch Sniffy from your application menu, or run `sniffy` in a terminal.

There is no package for other distributions yet. Build from source, or run the headless service in a container.

## Headless service

Headless binaries are named `sniffy-<os>-<arch>`. They run as soon as you download them, with nothing else to install:

<Downloads edition="headless" />

```bash
chmod +x sniffy-linux-amd64
./sniffy-linux-amd64 -version
./sniffy-linux-amd64
```

The second line only prints the version, to confirm the download is intact; the third starts the service.

The proxy listens on port `8080` by default, and devices on the same LAN can connect to it directly. The management API is on local port `8888` and requires a token; the path of the token file is printed in the log on first start. For ports, tokens, and deployment, see [Headless service](/en/docs/headless/).

## Build from source

You need Go 1.26+, plus Node.js 22.12+ for the desktop app. The build script is bash; on Windows, run it under Git Bash.

```bash
git clone https://github.com/mintfog/sniffy.git
cd sniffy
```

Build the headless service, for as many platforms as you like; output goes to `dist/`:

```bash
bash scripts/build.sh headless linux/amd64 darwin/arm64 windows/amd64
```

Build the desktop app; the output is `dist/sniffy-desktop` (`sniffy-desktop.exe` on Windows):

```bash
bash scripts/build.sh desktop
```

On macOS and Linux, the desktop build needs the system webview development packages installed first (WebKitGTK and its headers on Linux). Windows needs nothing extra.

## Where data lives

| Purpose       | Location                                                           |
| ------------- | ------------------------------------------------------------------ |
| Configuration | Linux `~/.config/sniffy`, macOS `~/Library/Application Support/sniffy`, Windows `%AppData%\sniffy` |
| Cache         | Linux `~/.cache/sniffy`, macOS `~/Library/Caches/sniffy`, Windows `%LocalAppData%\sniffy` |

Configuration holds `config.json`, `rules.json`, logs, user plugins, and certificates. Both editions read this one copy.

The cache only holds things that can be fetched again, such as large response bodies. You can delete it at any time. Full details in the [Configuration reference](/en/docs/configuration/).

## Upgrading

### Desktop app

When a new version is available, a notice appears in the status bar. Click it and download the installer from the About window; it's saved to your Downloads folder. Then finish the install for your platform:

- **Windows**: click "Install Now" and approve the system permission prompt. Sniffy closes and reopens automatically when installation finishes.
- **macOS**: click "Open Disk Image", quit Sniffy, then drag Sniffy from the disk image into Applications and replace the existing version.
- **Linux**: click "Show in Folder", quit Sniffy, then run `sudo apt install ./sniffy-desktop-linux-amd64-installer.deb`.

Rules, plugins, and the root certificate live in the configuration directory, and installing over the old version leaves them alone.

Automatic checks can be turned off in Settings - About. "Skip This Version" in the About window skips only the current version; you'll be notified again when the next one comes out.

### Headless service

The headless service only mentions new versions in its log; it doesn't install anything itself. Download the new executable from the section above, replace the old file, and restart the service. Your configuration carries over.

## Uninstalling

Remove Sniffy in "Apps & features" on Windows, delete the app on macOS, or run `sudo apt remove sniffy` on Linux.

Uninstalling removes only the program. The configuration and cache directories stay, and so does Sniffy Root CA in your system trust store. If you're done with Sniffy, delete those two directories yourself, then remove the root certificate from the trust store following [Removing the root certificate](/en/docs/https/#removing-the-root-certificate). Deleting the directories isn't enough: as long as the certificate is in the trust store, your system keeps trusting it.
